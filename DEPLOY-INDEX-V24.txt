DETERMINISM AUDIT
Session 1:
- score is recomputed from the exact confirmed choice sequence;
- each choice ID maps to one fixed effect table;
- the next consequence is rendered from the same stored choice;
- no random function is used in the Session 1 decision engine.

Sessions 2–7:
- each option has a fixed score delta;
- scores are recomputed from the confirmed choice sequence;
- outcome screen uses the selected option ID and the same fixed tables;
- no Math.random() occurs in group-sessions.js.

Therefore, with the same starting state and the same confirmed choices, two devices receive the same:
- consequence/outcome screen;
- decision code;
- points after each decision;
- final scores/profile.

Local storage only preserves progress per device; it does not alter scoring.
